## 1. AI 에이전트의 정의

**한 줄 정의**

목표 하나를 주면 스스로 계획을 세우고, 도구를 골라 쓰며, 끝날 때까지 일을 해내는 AI.

**상세 정의**

- 환경을 관찰(observation)하고, 보유한 도구(tools)로 행동(action)하며 목표를 달성하는 자율적인 소프트웨어 시스템이다.
- 명시적인 인간의 지시 없이도 목표를 판단하고, 이를 달성할 행동을 스스로 계획한다.

**핵심 특징**

| 특징 | 의미 |
| --- | --- |
| 자율성 (Autonomy) | 매번 지시받지 않고 스스로 판단하고 행동한다 |
| 적응성 (Adaptability) | 정해진 규칙이 아니라 상황을 분석해서 대응한다 |

**핵심 메커니즘**

- '인식 -> 계획 -> 실행 -> 평가'의 반복 루프
- 도구의 사용

---

## 2. 챗봇과의 차이점

- 챗봇: 답을 '말해주는' AI
- 에이전트: 루프를 돌며 직접 '해내는' AI

| 구분 | 챗봇 | AI 에이전트 |
| --- | --- | --- |
| 동작 | 질문 -> 답변 | 목표 -> 계획 -> 실행 -> 평가 (루프) |
| 자율성 | 낮음 (매번 지시 필요) | 높음 (스스로 판단·실행) |
| 도구 사용 | 제한적 | 웹·파일·코드·API 직접 호출 |
| 기억 | 대화 내 단기 기억 | 장기 기억 + 컨텍스트 유지 |

---

## 3. AI 에이전트의 동작 메커니즘

**루프 구조**

```
인식 -> 계획 -> 실행 -> 평가
         ^            |
         └── 실패 시 ───┘
```

| 단계 | 하는 일 | 예시 |
| --- | --- | --- |
| (1) 인식 (Perceive) | 요청과 환경을 파악 | 파일 구조, 로그 확인 |
| (2) 계획 (Plan) | 어떤 도구를 어떤 순서로 쓸지 결정 | 작업 순서 설계 |
| (3) 실행 (Act) | 실제로 도구를 호출 | 검색, 파일 수정, API 호출 |
| (4) 평가 (Evaluate) | 목표 달성 여부 확인 | 실패 시 (2)로 돌아감 |
- 이 루프를 반복하며 점점 나은 결과를 만드는 것이 에이전트의 원리다.
- Claude Code도 이 4가지 핵심으로 동작한다.

## 4. 하네스와 하네스 엔지니어링

### 4-1. 하네스 (Harness)

**정의**

- AI 모델이 실제 작업을 수행할 수 있도록 모델을 감싸는 소프트웨어 인프라이자 작업 환경이다.
- 모델은 '말'을 만들 뿐이고, 검색이나 코드 실행 같은 '손발'을 붙여주는 쪽이 하네스다.

> **에이전트 = 모델 + 하네스**
>

**역할 분담**

- 모델: 컨텍스트를 읽고 다음에 수행할 작업을 결정한다.
- 하네스: 모델을 도구, 메모리, 외부 시스템에 연결해 그 결정을 행동으로 전환한다.

**하네스의 구성 요소**

| 요소 | 내용 |
| --- | --- |
| 도구 | API, 코드 실행, 검색, 데이터베이스, 비즈니스 애플리케이션 |
| 메모리 | 이전 컨텍스트, 사용자 선호도, 워크플로 이력 |
| 작업 공간 | 에이전트가 접근할 수 있는 파일, 데이터, 환경, 시스템 |
| 가드레일 | 권한, 정책, 승인, 모니터링 |

**하네스가 없다면?**

모델은 질문에 답할 수는 있지만 다음은 안정적으로 하지 못한다.

- 코드 실행, API 호출, 파일 접근
- 이전 작업 기억
- 다단계 워크플로 완료

**모델 / 하네스 / 에이전트 비교**

| 구성 요소 | 역할 | 비유 |
| --- | --- | --- |
| 모델 | 추론, 예측, 텍스트 등 출력 생성 | 시스템의 '두뇌' |
| 하네스 | 행동 실행, 메모리 관리, 도구 실행, 규칙 적용 | 두뇌를 둘러싼 '몸'과 작업 공간 |
| 에이전트 | 둘이 결합된 전체 작동 시스템 | 생각하고 행동하는 '작업자' |

### 4-2. 하네스 엔지니어링 (Harness Engineering)

**정의**

AI 에이전트가 필요한 정보를 참고하고, 도구를 사용하고, 결과를 검증할 수 있도록 작업 환경을 체계적으로 설계하는 접근. 본질적으로 'AI가 일하는 환경을 잘 설계하는 방법'이다.

**등장 배경**

- 에이전트가 같은 오류를 반복하거나 프로젝트 규칙을 놓치는 문제가 생긴다.
- 좋은 프롬프트만으로는 부족하다 -> AI가 어떤 환경에서, 어떤 기준과 절차로 일할지까지 설계해야 한다.
- 에이전트를 '잘 만드는 것'만큼 '안정적으로 일하게 하는 것'이 중요해졌다.

**구성 요소 4가지**

| 영역 | 핵심 질문 | 내용 | 예시 |
| --- | --- | --- | --- |
| (1) 컨텍스트와 상태 관리 | 무엇을 참고할까? | 따라야 할 기준과 진행 기록을 관리해 작업을 이어갈 수 있게 함 | CLAUDE.md, AGENTS.md |
| (2) 도구와 실행 환경 | 무엇을 할 수 있을까? | 파일 읽기·수정, 명령 실행 등 에이전트가 쓰는 환경 | MCP |
| (3) 작업 흐름과 제어 | 어떻게 일할까? | 반복 절차 자동화 + 해서는 안 되는 행동 제한 (위험 명령 차단, 수정 후 자동 린트 등) | 훅 (Hooks) |
| (4) 검증과 피드백 | 결과가 맞을까? | 테스트·린트·빌드로 확인하고, 문제가 있으면 그 결과로 다시 수정 | 테스트, 린트, 빌드 |

## 5. 컨텍스트 윈도우 (Context Window)

**개념**

- 모델이 한 번에 기억하고 처리할 수 있는 텍스트의 총량이다.
- 단위는 토큰(token)이다.
- '컨텍스트 윈도우 = 입력 + 출력의 총합' -> 입력이 아주 길면 답변 분량이 짧아질 수 있다.
- 크기가 클수록 긴 대화나 문서를 맥락을 유지한 채 다룰 수 있다.

**컨텍스트 윈도우에 함께 들어가는 것**

- 대화 내용
- 읽은 파일
- 명령 실행 결과
- CLAUDE.md와 자동 메모리
- 불러온 스킬
- 시스템 지침

**한계와 문제**

- 대화가 턴을 거칠수록 메시지와 응답이 누적된다.
- 한도를 넘으면 오래된 내용부터 잃게 된다 (일반적으로 '슬라이딩 윈도우' 방식이라 부름) -> 대화가 길어질수록 맥락을 놓치는 이유.
- Claude Code에서는 한계에 가까워지면 대화를 자동으로 요약한다. 이를 **압축(compaction)** 이라고 한다.
    - 요청과 핵심 코드 조각은 남지만, 대화 초반의 세부 지시는 사라질 수 있다.
    - API를 직접 호출할 때는 자동 압축이 일어나지 않는다.

**관리 명령어 (Claude Code)**

| 명령어 | 기능 |
| --- | --- |
| `/context` | 컨텍스트 사용량 확인 |
| `/compact` | 직접 압축 |
| `/clear` | 무관한 작업을 시작할 때 대화 비우기 |
| `claude --continue` | 직전 세션 이어가기 |
| `claude --resume` | 이전 세션을 골라 이어가기 |
- 새 세션은 이전 대화 없이 시작한다.

## 6. CLAUDE.md

**문제 상황**

- Claude Code는 한 번의 대화를 '세션'이라 부른다.
- 새 세션은 백지 상태 -> 이전 대화나 정한 규칙을 기억하지 못한다.

**해결: CLAUDE.md**

- 프로젝트에 두는 마크다운 파일로, 세션 시작 시 컨텍스트에 자동으로 주입된다.
- 작업 규칙, 선호사항, 프로젝트 정보를 한 번만 적어두면 매번 반복할 필요가 없다.

**사용 팁**

- 파일당 200줄 미만을 권장한다.
- 강제 설정이 아니라 '컨텍스트'로 읽힌다 -> 반드시 막아야 할 동작은 훅으로 구현한다.
- `/init`으로 프로젝트를 분석해 시작용 CLAUDE.md를 만들 수 있다.

## 7. MCP, 스킬, 훅, 서브에이전트

이번 발표에서는 개념만 짚고 넘어간다.

| 기능 | 한 줄 설명 | 쓰임새 |
| --- | --- | --- |
| MCP (Model Context Protocol) | AI 애플리케이션을 외부 시스템에 연결하는 오픈 소스 표준 | Notion, Slack 등에 접근해 작업 |
| 스킬 (Skills) | 지식, 스크립트, 참고 자료를 하나의 폴더로 묶은 '전문 지식 패키지' | 특정 업무의 '업무 매뉴얼' 역할 |
| 훅 (Hooks) | 도구 사용, 세션 시작·종료 시점에 자동 실행되는 스크립트 | 저장 후 자동 포맷팅, 위험 명령 차단, 알림 전송 |
| 서브에이전트 (Subagents) | 메인 세션 안에서 실행되는 전문 에이전트. 독립된 컨텍스트 윈도우, 시스템 프롬프트, 도구 권한을 가지고 작업한 뒤 결과만 반환 | 컨텍스트 보존, 제약 적용, 구성 재사용, 동작 특화, 비용 제어 |

**교육 목표 4번 대비: 한눈에 구분하기**

| 기능 | 핵심 키워드 | 강제력 |
| --- | --- | --- |
| CLAUDE.md | 매 세션 자동으로 읽는 '규칙 메모' | 없음 (참고용 컨텍스트) |
| 훅 | 특정 시점에 '반드시' 실행 | 있음 (확정적 실행) |
| 스킬 | 필요할 때 꺼내 쓰는 '업무 매뉴얼' | 없음 |
| MCP | 외부 시스템과 연결하는 '표준 플러그' | - |
| 서브에이전트 | 독립 컨텍스트로 일하는 '전문 팀원' | - |
