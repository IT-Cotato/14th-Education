**브라우저 렌더링 단계**

1. 요청과 응답: 브라우저는 HTML, CSS, JS, 이미지, 폰트 등 리소스를 서버에 요청하고, 응답으로 받아온다.
2. 브라우저 렌더링 엔진은 받아온 HTML, CSS를 파싱해 DOM, CSSOM을 생성하고, 이들을 결합해 렌더 트리를 생성한다.
3. 브라우저 JS 엔진은 받아온 JS를 파싱해 AST를 생성하고, 바이트코드로 변환해 실행한다.
4. 레이아웃 계산: 렌더트리를 기반으로 HTML 요소의 레이아웃(위치, 크기)을 계산한다.
5. 페인팅: 화면에 HT**ML요소를 그린다.**

**→ 위 흐름에서 HTML에 들어가는 누가 언제 만드느냐를 정하는 앞 단계: 웹 렌더링 방식**

- **관련 용어 정리**
    
    **HTML:** 웹 페이지의 구조와 의미를 정의하는 표준 마크업 언어, "이 페이지에 무엇이 있는가"(제목, 문단, 이미지, 링크)를 적은 문서
    
    **CSS**: 요소가 어떻게 보일지(색, 크기, 배치)를 정하는 스타일 규칙 언어, "어떻게 보이게 할까"를 적은 규칙
    
    **JavaScript(JS)**: 웹페이지를 움직이고 반응하게 만드는 프로그래밍 언어
    
    리소스: 페이지를 구성하는 파일 전체(HTML, CSS, JS, 이미지, 폰트 등)
    
    **브라우저 렌더링 엔진:** HTML과 CSS를 해석해서 화면에 그리는 브라우저 내부 구성요소
    
    **브라우저 JS 엔진**: JavaScript 코드를 해석하고 실행하는 구성요소
    
    **DOM**: HTML 문서를 객체의 트리로 표현한 구조(문서의 구조도)
    
    **CSSOM**: CSS 규칙을 객체의 트리로 표현한 구조(스타일 정보)
    
    **렌더 트리**: DOM과 CSSOM 결합해 화면에 실제로 그려질 요소와 그 스타일만 담은 트리
    
    **페인팅**: 렌더 트리와 계산된 레이아웃을 바탕으로 실제 픽셀을 화면에 그리는 단계
    

# 2. 웹 렌더링 방식

렌더링이란: 웹 페이지의 HTML 콘텐츠를 최종적으로 만들어내는 과정

→ 한 마디로 사용자가 브라우저에서 실제로 보게 될 HTML 콘텐츠를 누가, 어디서, 언제 만들어내느냐

## **종류**

1. **클라이언트 측 렌더링(Client Side Rendering, CSR):** 브라우저가 HTML을 생성
2. **서버 측 렌더링(Server Side Rendering, SSR):** 요청이 올 때마다 서버가 문서를 생성
3. 정적 사이트 생성(Static Site Generation, SSG): 빌드할 때 HTML 콘텐츠를 미리 생성
4. 증분 정적 재생성(Incremental Static Regeneration, ISR): 미리 생성하되 일정 주기로 재생성

## CSR

![출처: [https://medium.com/walmartglobaltech/the-benefits-of-server-side-rendering-over-client-side-rendering-5d07ff2cefe8](https://medium.com/walmartglobaltech/the-benefits-of-server-side-rendering-over-client-side-rendering-5d07ff2cefe8)](./images/image%203.png)

출처: [https://medium.com/walmartglobaltech/the-benefits-of-server-side-rendering-over-client-side-rendering-5d07ff2cefe8](https://medium.com/walmartglobaltech/the-benefits-of-server-side-rendering-over-client-side-rendering-5d07ff2cefe8)

**클라이언트 측 렌더링 (CSR):** 웹 브라우저에서 JavaScript를 사용하여 웹페이지를 렌더링 하는 방식

사용자의 브라우저가 서버로부터 데이터를 받아와서 웹 페이지를 직접 생성

**동작 과정**

1. 사용자가 웹사이트에 접속하면 서버는 빈 HTML과 JavaScript 파일을 보낸다.
2. 브라우저가 JavaScript를 로드하고 실행한다.
3. JavaScript가 동적으로 HTML을 생성하고, 이를 브라우저에 표시한다.
4. 추가 페이지 요청 시, 전체 페이지를 다시 로드하는 대신 필요한 데이터만 서버에서 받아와서 해당 부분만 업데이트한다.

**비유**

CSR은 서버로부터 빈 접시(빈 HTML)와 요리 재료(JS)를 받고, 요리(렌더링)를 직접 하는 방식.

가정에서 직접 요리를 하는 홈 쿠킹과 비슷함, 자유롭게 요리를 할 수 있지만, 요리 실력(브라우저 성능)에 따라 결과가 달라질 수 있음.

### 특징

**장점**

- **서버 응답 시작 시간(TTFB) 빠름**:  서버가 빈 HTML을 바로 보내주기 때문에 서버 응답이 빨리 시작됨.
- **빠른 인터랙션 제공**: 초기 로딩 후, 필요한 데이터만 서버에서 가져와 동적으로 페이지를 업데이트하기 때문에 추가 페이지 로딩이 없음. 이로 인해 사용자와의 인터랙션이 빠르게 이루어짐.
- **서버 부하 감소**: 전체 페이지를 매번 새로 렌더링 하지 않고, 변화가 있는 부분만 업데이트하므로 서버에 부담을 덜어줌.

**단점**

- **브라우저 성능에 의존**: 브라우저 성능이 좋으면 웹 페이지의 렌더링 속도도 빠르고 사용자 경험도 좋아짐.
    
    하지만 브라우저 성능이 낮거나, JavaScript를 지원하지 않는 경우에는 웹 페이지의 렌더링 속도가 느려지거나, 웹 페이지가 제대로 표시되지 않을 수 있음. 
    
- **초기 로딩 속도 느림**: 브라우저가 JavaScript를 로드하고 실행하는 과정이 필요하므로, 이 과정으로 인해 초기 로딩 속도가 느릴 수 있음.
- **SEO/공유 미리보기 취약**

### **SEO/공유 미리보기 취약**

- **SEO: 검색 엔진 최적화(Search Engine Optimization)**
- 웹사이트가 구글, 네이버 등 검색 엔진의 검색 결과 페이지에 웹사이트가 더 잘 보이도록 최적화하는 과정
- 검색 엔진 동작 원리: 크롤러(검색 엔진의 로봇)가 인터넷의 페이지를 읽어 오고, 그 내용을 분석해 검색 결과의 순위를 정함. 크롤러가 처음 받는 HTML에 어떤 내용이 들어 있느냐에 따라 검색 노출 결과가 달라짐.
- 브라우저가 JavaScript를 실행하여 동적으로 만드는데, 이 과정이 실행되기 전에는 빈 HTML이 먼저 화면에 보이게 됨. 이 때문에 웹 크롤러가 페이지의 내용을 제대로 인식하지 못하여, 검색 엔진 최적화(SEO)에 취약할 수 있음.

**공유 미리보기**

- 카카오톡 등에 링크를 공유할 때 나오는 미리보기도 같은 원리임. 미리보기 봇은 JavaScript를 실행하지 않고 처음 받은 HTML 안의 제목과 이미지 정보만 읽기 때문에, CSR 구조에서는 미리보기가 제대로 만들어지지 않을 수 있음.

**적합한 상황**

- 사용자와의 상호작용이 많은 웹사이트에 적합.
- 사용자의 입력에 따라 화면이 동적으로 변하는 경우와 SEO가 크게 중요하지 않은 경우에 활용 가능.
- 예시) 대시보드, 어드민 페이지

## SSR

![출처: [https://medium.com/walmartglobaltech/the-benefits-of-server-side-rendering-over-client-side-rendering-5d07ff2cefe8](https://medium.com/walmartglobaltech/the-benefits-of-server-side-rendering-over-client-side-rendering-5d07ff2cefe8)](./images/image%204.png)

출처: [https://medium.com/walmartglobaltech/the-benefits-of-server-side-rendering-over-client-side-rendering-5d07ff2cefe8](https://medium.com/walmartglobaltech/the-benefits-of-server-side-rendering-over-client-side-rendering-5d07ff2cefe8)

**서버 측 렌더링 (SSR): 서버에서 HTML을 완성**하여 **브라우저**로 보내는 방식

**동작 과정**

1. 사용자가 웹사이트에 접속하면 서버에서 해당 페이지에 필요한 HTML을 생성한다.
2. 서버는 생성된 HTML을 브라우저로 전송한다.
3. 브라우저는 받은 HTML을 표시한다.
    1. **하이드레이션**: 클라이언트 측에서 자바스크립트를 통해 추가적인 기능(예: 이벤트 처리, 상태 관리 등)을 활성화하는 과정
4. 추가 페이지 요청 시, 해당 페이지에 대한 HTML을 다시 서버에서 생성하여 전송한다.

**비유**

서버에서 요리(웹페이지 렌더링)를 완성시킨 후 접시에 담아서(완성된 HTML) 손님(사용자)에게 제공하는 방식.

레스토랑에서 요리사가 완성된 요리를 손님에게 제공하는 것과 비슷함.

### **하이드레이션**

: 서버에서 렌더링된 정적 HTML에 자바스크립트 코드를 결합하여, 이벤트 리스너가 작동하는 인터랙티브한 애플리케이션으로 변화시키는 과정

1. **서버사이드 렌더링 (SSR)**:
    - 서버에서 미리 렌더링된 HTML이 클라이언트에게 전달됨.
    - 이 HTML은 이미 완성된 구조를 가지고 있으나, 자바스크립트 로직은 아직 적용되지 않은 상태임.
2. **하이드레이션**:
    - 클라이언트 측에서 자바스크립트가 로드됨.
    - 자바스크립트는 기존의 HTML과 연결되어 이벤트 리스너, 상태 관리, 기타 동적 기능을 활성화함.
    - 이 과정을 통해 서버에서 받은 정적인 HTML이 클라이언트 측에서 동적인 웹 애플리케이션으로 변환됨.

### 특징

**장점**

- **빠른 초기 페이지 로딩**: 서버에서 완성된 HTML을 브라우저로 보내주기 때문에, 사용자는 빠르게 완성된 페이지를 볼 수 있음.
- **검색 엔진 최적화·공유 미리보기에 유리**: 완성된 HTML을 제공하므로, 검색 엔진이 콘텐츠를 쉽게 인식하고 인덱싱할 수 있음.

**단점**

- **TTFB가 느려질 수 있음**: SSR은 서버가 화면을 그려주기까지 한 다음 브라우저로 보내기 때문.
- **서버 부하 증가**: 사용자의 각 요청에 대해 서버에서 렌더링을 해야 하므로, 서버 부하가 커질 수 있습니다.
- **하이드레이션 에러**: 서버에서 미리 그린 HTML과 클라이언트(브라우저)에서 자바스크립트를 실행해 처음 렌더링한 결과물이 서로 다를 때 발생

**적합한 상황**

- 동적 콘텐츠가 많은 웹사이트에 적합.
- 사용자의 요청에 따라 콘텐츠가 실시간으로 변경되어야 하는 경우, 서버에서 렌더링을 통해 항상 최신 상태의 웹 페이지를 제공할 수 있음.
- 예시) 사용자 맞춤형 콘텐츠를 제공하는 웹사이트, 주식 정보와 같이 실시간으로 변경되는 데이터를 다루는 웹사이트

| 항목 | CSR | SSR |
| --- | --- | --- |
| 서버 응답 시작(TTFB) | 빠름 | 느려질 수 있음 |
| 첫 화면 속도 | 느림 | 빠름 |
| 페이지 전환·인터랙션 | 빠름 | 상대적으로 느림 |
| 서버 부담 | 적음 | 큼 |
| SEO·공유 미리보기 | 불리 | 유리 |
| 한 줄 정리 | 처음은 느리고 이후가 빠름 | 처음은 빠르고 서버가 힘듦 |

# 3. 실제 사례

## 토스

> 토스는 이전에 CSR(Client Side Rendering) 아키텍처를 사용하고 있었는데요. 사용자의 화면에 JavaScript 번들이 모두 다운로드된 다음 첫 렌더링을 실행하면서 인증, 데이터 요청 등의 과정을 거치다보니 화면이 렌더링되는 시간이 상대적으로 길었습니다.

이때 SSR 아키텍처를 도입하게 되면서, 인증과 데이터 처리의 첫 과정이 서버에서 먼저 모두 이루어진 다음 사용자는 완성된 HTML을 받아보면서 로딩 속도를 상당히 감축할 수 있었습니다.

# 선택 기준

1. 검색 노출, 공유 미리보기가 필요한가
    
    →필요하다면 SSR을 사용, 필요 없다면 CSR을 사용해도 OK
    
2. 상호작용이 많은가
    
    → 상호작용이 많으면 CSR이 유리
    로딩 시간을 줄이려면 첫 페이지는 SSR, 이후는 CSR로 이어가는 SSR → CSR 구조 가능
    
3. 서버를 운영할 여건이 되는가
    
    →SSR에는 서버와 비용이 따라오니 주의
